# FLUX.2 klein-base-4B: CFG の強さと境界への忠実さ

## 条件
- モデル：`black-forest-labs/FLUX.2-klein-base-4B` + LoRA `ckpt/ramen_flux2/checkpoint-3000`
- 入力：`examples_Ramen` の 10 例（seed は各 json）。512×512、20 ステップ、hard マスク
- GPU：RTX 6000 Ada 1 枚（gp13）。作成は `scripts/flux2_cfg_sweep.py`
- 条件名
  - `cfgX`：ネガティブ側にも cond（輪郭）を入れる。**これまでの設定**。`cfg1.0` は CFG なし
  - `cfgX_negnocond`：ネガティブ側から cond を外す（新しく追加したオプション `negative_use_cond=False`）

## 境界の指標
- **recall**：マスクの境界画素のうち、生成画像の Canny エッジが 3px 以内にある割合。高いほど、マスクの境界の位置に実際の境目がある。
- **precision**：生成画像のエッジのうち、マスク境界の 3px 以内にある割合。麺などの模様のエッジも数えるので、値は全体に低めになる。
- 指標が機能することの確認：元写真とそのマスクでは recall 0.59、別の写真のマスクと組み合わせると 0.25。
- 元写真の値（0.59）は上限ではない。実写は境界がぼけていたり、アノテーションが粗かったりするため。生成画像は境界がくっきり出るので、元写真より高くなりうる。

## 結果（10 例の平均）

| 条件 | recall ↑ | precision | 秒/枚 |
|---|---|---|---|
| 元写真（参考） | 0.590 | 0.295 | – |
| **FLUX.1-dev + LoRA（既存出力）** | **0.843** | 0.334 | – |
| cfg1.0（CFG なし） | 0.484 | 0.309 | 3.49 |
| cfg1.5 | 0.497 | 0.324 | 7.03 |
| cfg2.0 | 0.530 | 0.332 | 7.24 |
| cfg3.0 | 0.608 | 0.309 | 7.32 |
| cfg4.0（**これまでの設定**） | 0.646 | 0.288 | 7.35 |
| cfg2.0_negnocond | 0.688 | 0.361 | 6.25 |
| **cfg4.0_negnocond** | **0.838** | 0.310 | 6.25 |

## わかったこと
1. **「FLUX.1 より境界に忠実でない」という印象は数値でも確認できた**。これまでの設定（cfg4.0）は 0.646 で、FLUX.1 の 0.843 より明らかに低い。
2. **ネガティブ側から cond を外すと、FLUX.1 と同じ水準（0.838）まで戻る**。見た目でも、丼の外周やチャーシュー・メンマの輪郭がマスクの境界によく沿う（`zoom_boundary_overlay.jpg`）。輪郭線をそのまま描いてしまうような破綻は無い。
3. 理由：CFG は「ポジティブの予測 − ネガティブの予測」を guidance_scale 倍して強調する。ネガティブ側にも同じ cond を入れると、輪郭の効果はこの差に入らず、**輪郭は等倍のまま、テキストだけが 4 倍に強調される**。ネガティブ側から cond を外すと、輪郭の効果も差に入り、テキストと一緒に強調される。
4. ネガティブ側に cond を入れたままでも、CFG を上げると recall は上がる（0.48 → 0.65）。CFG で画像全体のコントラストが上がり、境目がくっきりするためと考えられる（precision はむしろ下がる）。
5. ネガティブ側の系列に cond トークンが無くなる分、少し速くなる（7.35 → 6.25 秒/枚）。
